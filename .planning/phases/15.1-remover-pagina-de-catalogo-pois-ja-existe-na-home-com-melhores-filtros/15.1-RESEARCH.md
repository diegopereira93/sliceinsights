**Researched:** 2026-03-22

## Summary

A fase 15.1 é uma tarefa de limpeza cirúrgica: remover a rota `/catalog` do Next.js App Router e todos os artefatos exclusivos a ela, pois a home page (`/`) já oferece capacidade de filtro equivalente (e superior em UX) com o `FilterDrawer`, busca por texto, comparação e quiz inline.

O escopo total é apenas frontend. O backend API (`/api/v1/catalog/paddles` e `/api/v1/catalog/stores`) e seus testes Python NÃO devem ser tocados — esses endpoints são consumidos pela home page indiretamente via `lib/api.ts` e pelo assistente de IA. O e2e test suite referencia `/catalog` apenas em comments e strings de texto, não em navegação direta — pode ser atualizado sem risco de quebrar cobertura crítica.

A diferença funcional entre as duas páginas é real: a home usa o tipo `Paddle` (mapeado de `/api/v1/paddles`), filtragem client-side em memória, busca por texto, comparador lado-a-lado e quiz. O `/catalog` usa o tipo `CatalogPaddle` (de `/api/v1/catalog/paddles`), filtragem server-side com SSR, paginação de 24 itens e exibe preços de múltiplas lojas diretamente. Isso significa que o tipo `CatalogPaddle` e os componentes `catalog/` são usados SOMENTE pela página de catálogo — podem ser deletados em conjunto.

**Recomendação primária:** Deletar a rota `/catalog` e todos os artefatos exclusivos dela em um único commit atômico, substituir o `NavItem "Catalogo"` no bottom-nav por `NavItem "Recomendação"` apontando para `/recommend`, e remover a entrada `/catalogo` do sitemap.

## Análise de Dependências Cruzadas

### `FilterDrawer` — componente COMPARTILHADO

`FilterDrawer` em `frontend/components/paddle/filter-drawer.tsx` é usado por DOIS lugares:
- `frontend/components/home-client.tsx` (linha 24, 166-177)
- `frontend/app/catalog/catalog-client.tsx` (linha 11, 135-151)

Quando o catalog-client for deletado, `FilterDrawer` continua necessário para a home. **Não deletar.**

A prop interface do `FilterDrawer` na home vs catalog tem uma diferença:
- Home passa: `weightFilter`, `onWeightChange` (filtro de peso)
- Catalog passa: `storeFilter`, `onStoreChange`, `stores` (filtro por loja)

O `FilterDrawer` provavelmente aceita ambos como opcionais. Verificar se `storeFilter`/`onStoreChange`/`stores` podem ser removidos da interface do `FilterDrawer` após o delete do catalog — isso é uma limpeza opcional, não bloqueante.

### `CatalogFilterBar` — componente EXCLUSIVO do catalog

`CatalogFilterBar` em `frontend/components/catalog/catalog-filter-bar.tsx` importa apenas `CatalogFilters` de `@/types/catalog`. Quando o diretório `components/catalog/` for deletado, o arquivo de tipos também some.

### `SkeletonGrid` — exportado de catalog-grid, usado em catalog/page.tsx

`SkeletonGrid` é exportado de `frontend/components/catalog/catalog-grid.tsx` e usado APENAS em `frontend/app/catalog/page.tsx` (linha 4). Deletar ambos elimina o uso.

### E2E test — `sliceinsights.spec.ts`

O describe `'Catalog'` (linha 37) já navega para `/` (home), não para `/catalog`. O texto do describe e o comment na linha 5 mencionam "Catalog" mas a navegação é via `page.goto('/')`. Nenhum teste faz `page.goto('/catalog')`. A mudança necessária é apenas cosmética: renomear o describe para `'Home Catalog'` e atualizar o comment do arquivo. A cobertura não é afetada.

A linha 146 tem `text=/Catálogo|Resultado|Recomendação|catalog|result/i` — esse locator ainda funciona pois a home tem texto "EXPLORAR CATÁLOGO" e "Catálogo de Raquetes" nos cards.

## Common Pitfalls

### Pitfall 1: Deletar o diretório `app/catalog/` no filesystem mas esquecer o import no bottom-nav

**O que dá errado:** Next.js não falha em build por um link morto no bottom-nav — `<Link href="/catalog">` com a rota deletada resulta em 404 silencioso em runtime, não erro de build.

**Como evitar:** Modificar `bottom-nav.tsx` ANTES ou NO MESMO commit do delete da rota.

**Sinal de alerta:** Build passa, mas clicar em "Catalogo" no bottom-nav retorna tela 404.

### Pitfall 2: Deletar `types/catalog.ts` antes de confirmar que nenhum outro arquivo importa dele

**O que dá errado:** TypeScript build quebra em todos os arquivos que importam de `@/types/catalog`.

**Como evitar:** Verificar com grep antes de deletar. Os únicos consumidores são os próprios arquivos do diretório `catalog/` — todos sendo deletados juntos.

**Sinal de alerta:** `tsc` retorna `Cannot find module '@/types/catalog'`.

### Pitfall 3: Deletar a entrada do sitemap com URL errada

**O que dá errado:** O sitemap.ts tem a entrada como `/catalogo` (com "o" final, em pt-br), não `/catalog`. A rota Next.js é `/catalog`. São inconsistentes.

**Como evitar:** Remover a entrada com URL `${baseUrl}/catalogo` (linha 20-25 do sitemap.ts). Essa entrada já era incorreta (URL errada para a rota real), então a remoção limpa a inconsistência.

### Pitfall 4: Deixar o import de `ShoppingBag` órfão no bottom-nav

**O que dá errado:** Linter/build pode emitir warning sobre import não usado.

**Como evitar:** Ao remover o `NavItem` do `/catalog`, também remover `ShoppingBag` do import de `lucide-react` na linha 4 — se não for substituído por outro ícone.

## Architecture Patterns

### Next.js App Router — deletando uma rota

Deletar uma rota no App Router é simples: remover o diretório `app/[route]/` completo. O Next.js não precisa de configuração adicional para "desregistrar" a rota.

Se for desejado redirecionar usuários que tinham `/catalog` nos bookmarks, adicionar em `next.config.mjs`:

```javascript
async redirects() {
  return [
    { source: '/catalog', destination: '/', permanent: true },
  ];
},
```

Isso é opcional e não está no escopo padrão — mencionar como melhoria de UX.

### Bottom-nav após remoção

O bottom-nav atual tem 3 itens: `Home`, `Análise`, `Catalogo`. Com a remoção do Catalogo, as opções são:
1. Ficar com 2 itens (Home + Análise)
2. Substituir por `Recomendação` apontando para `/recommend`

A opção 2 é preferível em termos de UX — `/recommend` é uma funcionalidade de alto valor que atualmente não aparece na navegação principal.
