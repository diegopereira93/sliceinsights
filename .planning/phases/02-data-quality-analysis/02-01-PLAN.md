# Plan 02-01: Run All Audit Tools & Capture Raw Outputs

<objective>
Execute all four audit scripts inside the `backend_v3` Docker container and capture their raw outputs into artifact files. This provides the raw data that Plan 02-02 analyzes into structured deliverables.
</objective>

<must_haves>
- `audit_data_quality.py` stdout captured in `artifacts/audit_output.txt`
- `smoke_test_quality.py` stdout captured in `artifacts/smoke_test_output.txt`
- `measure_freshness.py` JSON output captured in `artifacts/freshness_report.json`
- `measure_coverage.py` JSON output captured in `artifacts/coverage_report.json`
- All four scripts exit normally (non-crash — note that smoke_test may exit 1 if checks fail, that's expected and informative)
</must_haves>

## Tasks

<task id="02-01-01" title="Run audit_data_quality.py and capture output">
<read_first>
- scripts/audit_data_quality.py (understand output format — 6 sections, summary table at end)
- .planning/phases/02-data-quality-analysis/artifacts/ (confirm directory exists from Plan 02-00)
</read_first>

<action>
Run the full data quality audit and capture both stdout and stderr:

```bash
docker compose exec -T backend_v3 python scripts/audit_data_quality.py \
  2>&1 | tee .planning/phases/02-data-quality-analysis/artifacts/audit_output.txt
```

**Expected output sections:**
1. FIELD COVERAGE — per-field completeness percentage bars
2. BR → US DUMP MATCH — fuzzy matching results
3. NON-PADDLE DETECTION — keyword-based filter results
4. DUPLICATE DETECTION — cross-store deduplication
5. MARKET OFFER CHECK — active offers per paddle
6. AUDIT SUMMARY — rollup metrics

**Warning signs:**
- "No paddles found in database. Audit skipped." → DB is empty, need to seed first
- "DATABASE_URL_SYNC" warning → env var not set, but script may still work with defaults
</action>

<acceptance_criteria>
- `.planning/phases/02-data-quality-analysis/artifacts/audit_output.txt` exists and is non-empty
- File contains the string "AUDIT SUMMARY" (confirms full execution)
- File contains "FIELD COVERAGE" section
- File contains "Total paddles:" line with a number > 0
</acceptance_criteria>
</task>

<task id="02-01-02" title="Run smoke_test_quality.py and capture output">
<read_first>
- scripts/smoke_test_quality.py (4 checks: specs confidence, fabricated ratings, market offers, required fields)
</read_first>

<action>
Run smoke tests and capture output (note: may exit 1 if tests fail — that's informative data, not an error):

```bash
docker compose exec -T backend_v3 python scripts/smoke_test_quality.py \
  2>&1 | tee .planning/phases/02-data-quality-analysis/artifacts/smoke_test_output.txt
echo "EXIT_CODE=$?" >> .planning/phases/02-data-quality-analysis/artifacts/smoke_test_output.txt
```

**4 checks performed:**
1. Specs Confidence Gate — no active paddle with confidence < 1.0
2. No Fabricated Ratings — no all-default (5,5,5) ratings
3. Market Offers Present — all active paddles have offers
4. Required Fields Complete — all 9 REQUIRED_FIELDS filled for active paddles
</action>

<acceptance_criteria>
- `.planning/phases/02-data-quality-analysis/artifacts/smoke_test_output.txt` exists and is non-empty
- File contains "SMOKE TEST" string
- File contains "CHECK 1:" through "CHECK 4:" (all 4 checks ran)
- File contains either "ALL SMOKE TESTS PASSED" or "SMOKE TESTS FAILED"
</acceptance_criteria>
</task>
