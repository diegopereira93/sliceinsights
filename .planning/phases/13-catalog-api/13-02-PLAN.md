    **Test architecture:** These are HTTP-level tests using `async_client` fixture which overrides `get_session` with an `AsyncMock`. The mock session's `.exec()` method must be configured to return appropriate mock results for each test.

    **Mock setup pattern for paddles tests:**
    ```python
    import pytest
    import pytest_asyncio
    from unittest.mock import AsyncMock, MagicMock, patch
    from uuid import uuid4
    from decimal import Decimal
    from tests.conftest import MockPaddle, MockStore, MockMarketOfferWithStore

    @pytest.mark.asyncio
    async def test_list_catalog_paddles(async_client):
        """CAT-01: GET /api/v1/catalog/paddles returns paddles list."""
        # Setup mock paddle with offers
        paddle = MockPaddle(name="Test Carbon 16")
        store = MockStore(name="ProPadel", slug="propadel")
        offer = MockMarketOfferWithStore(paddle_id=paddle.id, price=899.90, store=store)
        paddle.market_offers = [offer]

        # Mock session.exec to return results
        # The endpoint calls session.exec() multiple times:
        # 1. Main query returns list of (paddle, min_price) tuples
        # 2. Count query returns total
        mock_result = MagicMock()
        mock_result.all.return_value = [(paddle, Decimal("899.90"))]

        mock_count_result = MagicMock()
        mock_count_result.first.return_value = 1

        # Use side_effect for sequential exec calls
        with patch("app.api.endpoints.catalog.get_session") as mock_get_session:
            mock_session = AsyncMock()
            mock_session.exec = AsyncMock(side_effect=[mock_result, mock_count_result])
            mock_get_session.return_value.__aenter__.return_value = mock_session

            response = await async_client.get("/api/v1/catalog/paddles")

        assert response.status_code == 200
        data = response.json()
        assert "data" in data
        assert "total" in data
        assert "limit" in data
        assert "offset" in data
    ```

    **Important notes for test implementation:**
    - The `async_client` fixture already overrides `get_session` — so you need to configure the mock session that's yielded, not patch `get_session` separately. Look at how `async_client` works: it yields an `AsyncMock()` from `override_get_session`. You can configure this mock by intercepting calls.
    - Alternative simpler approach: since async_client overrides get_session with a mock that yields an AsyncMock, and the endpoint calls `session.exec()`, configure expectations on the mock session directly. The mock session is the `AsyncMock()` instance created inside the fixture.
    - For the stores endpoint, the mock pattern is simpler since there's only one query (no subquery).
    - For filter tests: You can verify the endpoint returns 200 and check the response shape. With mocked sessions, verifying the actual filter SQL is complex — focus on verifying that the endpoint accepts the query params without errors and returns the expected response structure.
    - For the 422 validation test (invalid surface_material), no mock setup needed — FastAPI validates before hitting the endpoint.
    - For the max limit test (limit=200), no mock setup needed — FastAPI Query validation rejects it.
    - Use `@pytest.mark.asyncio` decorator on all async tests.
