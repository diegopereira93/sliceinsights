**Endpoint 1: `GET /catalog/paddles`**

Query parameters (all optional):
- `core_thickness: Optional[List[float]] = Query(default=None)` — multi-value, e.g. `?core_thickness=13&core_thickness=16`
- `surface_material: Optional[List[str]] = Query(default=None)` — multi-value, e.g. `?surface_material=carbon&surface_material=hybrid`
- `price_min: Optional[float] = Query(default=None)`
- `price_max: Optional[float] = Query(default=None)`
- `brand: Optional[str] = Query(default=None)` — case-insensitive match on Brand.name via `.ilike()`
- `store: Optional[str] = Query(default=None)` — exact match on Store.slug
- `limit: int = Query(default=50, le=100)`
- `offset: int = Query(default=0, ge=0)`

Query construction strategy (avoids cartesian product pitfall from RESEARCH.md):

1. Build a **filtered offer subquery** that applies store filter INSIDE the subquery (not as a separate JOIN):
```python
offer_subq = (
    select(
        MarketOffer.paddle_id,
        func.min(MarketOffer.price_brl).label("min_price"),
    )
    .where(MarketOffer.is_active.is_(True))
)

# Apply store filter INSIDE offer subquery to avoid cartesian product
if store:
    offer_subq = (
        offer_subq
        .join(Store, MarketOffer.store_id == Store.id)
        .where(Store.slug == store)
    )

offer_subq = offer_subq.group_by(MarketOffer.paddle_id).subquery()
```

2. Main query uses **INNER JOIN** (not outerjoin) on offer_subq to enforce CAT-06 (only paddles with active offers):
```python
query = (
    select(PaddleMaster)
    .options(selectinload(PaddleMaster.brand))
    .options(
        selectinload(PaddleMaster.market_offers)
        .selectinload(MarketOffer.store)
    )
    .join(offer_subq, PaddleMaster.id == offer_subq.c.paddle_id)
)
```

3. Apply spec filters on PaddleMaster:
```python
if core_thickness:
    query = query.where(PaddleMaster.core_thickness_mm.in_(core_thickness))
if surface_material:
    # Normalize to lowercase to match FaceMaterial enum values
    normalized = [s.lower() for s in surface_material]
    query = query.where(PaddleMaster.face_material.in_(normalized))
```

4. Apply price filters on offer_subq.c.min_price:
```python
if price_min is not None:
    query = query.where(offer_subq.c.min_price >= price_min)
if price_max is not None:
    query = query.where(offer_subq.c.min_price <= price_max)
```

5. Apply brand filter via JOIN:
```python
if brand:
    query = query.join(Brand, PaddleMaster.brand_id == Brand.id).where(Brand.name.ilike(brand))
```

6. Count query: Build a SEPARATE count query applying the same filters (extract filter logic into a helper function to avoid the pitfall of mismatched filters between data and count queries). The count query must also use INNER JOIN on offer_subq.

7. Apply pagination: `.order_by(offer_subq.c.min_price.asc()).offset(offset).limit(limit)` — sort by cheapest offer price ascending (per user decision, natural for shopping catalog).

8. Build response: For each PaddleMaster, build `CatalogPaddleOut` with:
   - `brand`: `paddle.brand.name` (string, not ID)
   - `specs.surface_material`: `paddle.face_material.value if paddle.face_material else None` (enum value string)
   - `market_offers`: Filter to only `is_active=True` offers, map each to `CatalogOfferOut(store_name=offer.store.name, store_slug=offer.store.slug, price_brl=float(offer.price_brl), store_url=offer.url)`

9. Return envelope: `{"data": [CatalogPaddleOut...], "total": total_count, "limit": limit, "offset": offset}`

**Endpoint 2: `GET /catalog/stores`**

Query parameters:
- `brand: Optional[str] = Query(default=None)` — filter stores by available brand (uses PostgreSQL ARRAY containment)

```python
query = select(Store).where(Store.is_active.is_(True))
if brand:
    # PostgreSQL ARRAY containment: Store.available_brands.any(brand)
    query = query.where(Store.available_brands.any(brand))

results = await session.exec(query.order_by(Store.name))
stores = results.all()
return {
    "data": [CatalogStoreOut.model_validate(s) for s in stores],
    "total": len(stores)
}
```

**Rate limiting:** Import the limiter from main at function level to avoid circular imports:
```python
@router.get("/catalog/paddles", response_model=dict)
async def list_catalog_paddles(request: Request, ...):
    from app.main import limiter
    # Rate limiting via decorator won't work with function-level import
```

BETTER approach — use the SAME pattern as `routes.py`: create a local `Limiter` instance in `catalog.py`:
```python
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)

@router.get("/catalog/paddles", response_model=dict)
@limiter.limit("100/minute")
async def list_catalog_paddles(request: Request, ...):
```

This works because `app.state.limiter` in `main.py` is the one that handles the actual rate limiting state, and slowapi looks it up from `request.app.state.limiter`. The decorator's `Limiter` instance is only used for configuration. Confirm by checking how `routes.py` does it — it creates its own `limiter = Limiter(key_func=get_remote_address)` independently.
