    Create `scripts/deploy_worker.py` with the following structure (following alert_worker.py CLI pattern):

    **Imports:**
    ```python
    import argparse
    import hashlib
    import logging
    import sys
    from datetime import date, datetime, timezone
    from sqlalchemy import text
    from sqlalchemy.orm import Session
    from app.db.database import sync_engine
    ```

    **Core functions:**

    1. `generate_batch_id(batch_date: date) -> str`:
       - Format: `f"batch_{batch_date.strftime('%Y%m%d')}_{hashlib.md5(str(datetime.now(timezone.utc)).encode()).hexdigest()[:6]}"`
       - Returns human-readable batch identifier

    2. `get_next_version_id(conn) -> int`:
       - `SELECT COALESCE(MAX(version_id), 0) + 1 FROM deploy_logs WHERE status = 'published'`
       - Returns 1 if no previous deploys

    3. `cleanup_old_staging(conn, days: int = 7) -> int`:
       - `DELETE FROM market_offers_staging WHERE created_at < NOW() - INTERVAL ':days days'`
       - Returns count of deleted rows (TTL cleanup, Claude's discretion: 7 days)

    4. `aggregate_batch(conn, batch_id: str, batch_date: date, passed_scrapers: list[str]) -> tuple[int, list[str]]`:
       - For each scraper in passed_scrapers:
         ```sql
         INSERT INTO market_offers_staging (batch_id, paddle_id, store_name, price_brl, url, last_updated)
         SELECT :batch_id, paddle_id, store_name, price_brl, url, last_updated
         FROM market_offers
         WHERE store_name = :scraper_name
           AND last_updated >= :day_start
           AND last_updated < :day_end
           AND is_active = true
         ```
       - day_start = batch_date 00:00:00 UTC, day_end = batch_date+1 00:00:00 UTC
       - Returns (total_rows_inserted, list_of_scrapers_included)

    5. `publish_batch(conn, batch_id: str, version_id: int) -> int`:
       - Single transaction (conn is already inside sync_engine.begin()):
         a. Mark previous version inactive: `UPDATE market_offers SET is_active = false WHERE version_id = :prev_version` (prev = version_id - 1)
         b. Upsert from staging:
            ```sql
            INSERT INTO market_offers (paddle_id, store_name, price_brl, url, last_updated, is_active, version_id)
            SELECT paddle_id, store_name, price_brl, url, last_updated, true, :version_id
            FROM market_offers_staging
            WHERE batch_id = :batch_id
            ON CONFLICT (paddle_id, store_name)
            DO UPDATE SET
                price_brl = EXCLUDED.price_brl,
                url = EXCLUDED.url,
                last_updated = EXCLUDED.last_updated,
                version_id = EXCLUDED.version_id,
                is_active = true
            ```
         c. Return rowcount from upsert
       - NOTE: Requires UNIQUE constraint on (paddle_id, store_name) in market_offers — if not present, add it in the Alembic migration from 08-01 or handle via DELETE+INSERT pattern instead of ON CONFLICT.

    6. `rollback_batch(batch_id: str) -> None`:
       - Look up version_id from deploy_logs WHERE batch_id = :batch_id AND status = 'published'
       - Single transaction:
         a. `UPDATE market_offers SET is_active = false WHERE version_id = :current`
         b. `UPDATE market_offers SET is_active = true WHERE version_id = :previous` (current - 1)
       - Write DeployLog entry with status="rolled_back"
       - Print summary to stdout

    7. `prune_old_versions(conn, current_version_id: int) -> int`:
       - Keep current + 1 previous version. Delete older:
         `DELETE FROM market_offers WHERE version_id IS NOT NULL AND version_id < :keep_min`
         where keep_min = current_version_id - 1
       - Returns deleted count

    8. `force_publish(batch_id: str, operator_id: str) -> None`:
       - Skip validation, call publish_batch directly
       - Write DeployLog with forced=True, operator_id=operator_id
       - Send alert notification via SLOAlertService (import lazily to avoid circular):
         ```python
         try:
             from app.services.slo_alerts import SLOAlertService
             service = SLOAlertService()
             service.send_telegram(f"FORCE PUBLISH: batch {batch_id} by {operator_id}")
         except Exception:
             logging.warning("Failed to send force-publish alert")
         ```

    9. `run_deploy(batch_date: date | None = None) -> None`:
       - Main orchestration:
         a. batch_date defaults to date.today() (UTC)
         b. batch_id = generate_batch_id(batch_date)
         c. Open session, call check_slo_gate to get passed/failed scrapers
         d. If no scrapers passed: log failure, exit 1
         e. cleanup_old_staging(conn, 7)
         f. aggregate_batch(conn, batch_id, batch_date, passed_scrapers)
         g. Write DeployLog with status="pending"
         h. run_pre_deploy_validation(batch_id, batch_date) — if fails, update DeployLog to status="failed", exit 1
         i. Update DeployLog to status="validated"
         j. publish_batch(conn, batch_id, version_id)
         k. Update DeployLog to status="published", products_published=count, finished_at=now
         l. prune_old_versions(conn, version_id)
         m. Print summary to stdout

    10. `_build_parser() -> argparse.ArgumentParser`:
        - Mutually exclusive group:
          - `--run`: Run full nightly deploy pipeline
          - `--validate-batch BATCH_ID`: Re-run validation only (delegates to deploy_validator.py)
          - `--force-publish BATCH_ID`: Force publish bypassing validation
          - `--rollback BATCH_ID`: Rollback a specific batch
        - Optional args:
          - `--batch-date YYYY-MM-DD`: Override batch date (default: today UTC)
          - `--operator-id NAME`: Operator identifier for force-publish audit trail

    11. `def main() -> None`:
        - Parse args, dispatch to run_deploy / force_publish / rollback_batch / validate
        - Wrap in try/except, log errors, exit with code 0 or 1
