    ```yaml
    name: Nightly Batch Deploy

    on:
      repository_dispatch:

    jobs:
      deploy:
        name: Nightly Batch Deploy
        runs-on: ubuntu-latest
        timeout-minutes: 150

        steps:
          - name: Checkout code
            uses: actions/checkout@v4

          - name: Set up Python 3.11
            uses: actions/setup-python@v5
            with:
              python-version: '3.11'
              cache: 'pip'

          - name: Install dependencies
            run: |
              python -m pip install --upgrade pip
              pip install -r requirements.txt

          - name: Run nightly deploy
            run: |
              python scripts/deploy_worker.py --run
            env:
              DATABASE_URL_SYNC: ${{ secrets.DATABASE_URL_SYNC }}

      notify:
        name: Deploy Notification
        needs: deploy
        if: always()
        runs-on: ubuntu-latest

        steps:
          - name: Checkout code
            uses: actions/checkout@v4

          - name: Set up Python 3.11
            uses: actions/setup-python@v5
            with:
              python-version: '3.11'
              cache: 'pip'

          - name: Install dependencies
            run: |
              python -m pip install --upgrade pip
              pip install -r requirements.txt

          - name: Send deploy status alert
            if: needs.deploy.result == 'failure'
            run: |
              python scripts/alert_worker.py --all
            env:
              DATABASE_URL_SYNC: ${{ secrets.DATABASE_URL_SYNC }}
              TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
              TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
              GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
              GITHUB_REPOSITORY: ${{ github.repository }}
              ADMIN_EMAIL_GROUP: ${{ secrets.ADMIN_EMAIL_GROUP }}
              EMAIL_HOST: ${{ secrets.EMAIL_HOST }}
              EMAIL_PORT: ${{ secrets.EMAIL_PORT }}
              EMAIL_USER: ${{ secrets.EMAIL_USER }}
              EMAIL_PASSWORD: ${{ secrets.EMAIL_PASSWORD }}
    ```

    Create `docs/deploy-guide.md` with the following sections (follow docs/slo-guide.md style):

    **Title:** `# Deploy & Release Guide`

    **Section 1: Overview**
    - Nightly batch deployment pipeline overview
    - Event-driven trigger (repository_dispatch after scraper suite completes)
    - Pipeline stages: Aggregate -> Validate -> Publish -> Prune
    - Diagram showing data flow: scraper runs -> slo_logs -> staging -> validation gate -> production (versioned)

    **Section 2: Architecture**
    - Data flow description:
      1. Scrapers run and write to market_offers + slo_logs
      2. GitHub Actions fires `scrapers-complete` repository_dispatch
      3. deploy_worker.py --run begins
      4. check_slo_gate queries slo_logs for calendar day
      5. aggregate_batch copies passing scrapers' data to market_offers_staging
      6. run_pre_deploy_validation: SLO re-check + corruption audit
      7. publish_batch: atomic upsert from staging to market_offers with version_id tagging
      8. prune_old_versions: keep current + 1 previous
    - Key tables: market_offers, market_offers_staging, deploy_logs, slo_logs
    - Version schema: version_id INTEGER + is_active BOOLEAN on market_offers

    **Section 3: CLI Reference**
    ```
    # Full nightly deploy (normally triggered by GitHub Actions)
    python scripts/deploy_worker.py --run [--batch-date YYYY-MM-DD]

    # Re-validate a specific batch (check if staging data is clean)
    python scripts/deploy_worker.py --validate-batch BATCH_ID [--batch-date YYYY-MM-DD]

    # Force publish (bypass validation — use with caution)
    python scripts/deploy_worker.py --force-publish BATCH_ID --operator-id YOUR_NAME

    # Rollback a deployed batch (instant flag-flip, zero downtime)
    python scripts/deploy_worker.py --rollback BATCH_ID
    ```
    - Document each command with: purpose, when to use, example output, exit codes (0=success, 1=failure)

    **Section 4: Rollback Procedure**
    Step-by-step:
    1. Identify the batch to rollback: `SELECT batch_id, version_id, status FROM deploy_logs ORDER BY created_at DESC LIMIT 5`
    2. Run rollback: `python scripts/deploy_worker.py --rollback batch_20260319_2f4a8`
    3. Verify rollback: `SELECT COUNT(*) FROM market_offers WHERE is_active = true` (should match pre-deploy count)
    4. Rollback is guaranteed within 24h of deploy (after 24h, version N-2 may be pruned)
    5. Rollback does NOT delete the new version rows — they remain for audit with is_active=false

    **Section 5: Troubleshooting**
    | Problem | Cause | Solution |
    |---------|-------|----------|
    | Deploy aborted: 0 scrapers passed | All scrapers have SLO breaches | Check slo_logs: `SELECT * FROM slo_logs WHERE checked_at > NOW() - INTERVAL '24h' AND status = 'fail'`. Fix failing scrapers. |
    | Validation failed: NULL corruption | Staging data has NULL price_brl or url | Investigate source scraper. Run `SELECT * FROM market_offers_staging WHERE batch_id = 'X' AND price_brl IS NULL` |
    | Validation failed: SLO breach | Data quality degraded between aggregation and validation | Retry: `python scripts/deploy_worker.py --validate-batch BATCH_ID`. If confident it's a false positive, use --force-publish |
    | Rollback fails: no previous version | Version N-1 was already pruned (>24h since deploy) | Manual recovery: restore from database backup. Prevention: rollback within 24h window |
    | Deploy timeout (150min exceeded) | Scraper suite took too long | Check GitHub Actions logs. Increase timeout-minutes in deploy-nightly.yml if needed |
    | Webhook not firing | GH_DEPLOY_PAT expired or missing repo scope | Regenerate PAT with repo scope. Update GH_DEPLOY_PAT secret in GitHub repository settings |

    **Section 6: Deploy Logs**
    - `deploy_logs` table schema (all columns documented)
    - Example queries:
      - Last 5 deploys: `SELECT batch_id, version_id, status, scrapers_passed, products_published, created_at FROM deploy_logs ORDER BY created_at DESC LIMIT 5`
      - Failed deploys: `SELECT * FROM deploy_logs WHERE status = 'failed' ORDER BY created_at DESC`
      - Force-published: `SELECT * FROM deploy_logs WHERE forced = true`

    **Section 7: GitHub Actions Setup**
    - How to trigger manually: GitHub Actions tab -> "Nightly Batch Deploy" -> "Run workflow"
    - How to trigger from scraper pipeline: add `repository_dispatch` call to scraper CI "all done" job:
      ```yaml
      - name: Trigger deploy
        run: |
          gh api repos/${{ github.repository }}/dispatches \
            -f event_type=scrapers-complete
        env:
          GH_TOKEN: ${{ secrets.GH_DEPLOY_PAT }}
      ```
    - Required secrets: DATABASE_URL_SYNC, GH_DEPLOY_PAT (repo scope), TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, ADMIN_EMAIL_GROUP, EMAIL_HOST, EMAIL_PORT, EMAIL_USER, EMAIL_PASSWORD

    | DEP-05 | DeployLog model + deploy_worker.py logging | test_deploy_worker.py::test_deploy_log_written |
