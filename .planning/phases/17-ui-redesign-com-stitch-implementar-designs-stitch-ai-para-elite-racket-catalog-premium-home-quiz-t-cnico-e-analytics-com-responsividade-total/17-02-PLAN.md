    **Helper function — paddle_to_orval():**
    Create a helper that maps a PaddleMaster SQLModel instance (with loaded brand and market_offers relationships) to the Orval `Paddle` dict:
    ```python
    def paddle_to_orval(paddle: PaddleMaster, seq_id: int) -> dict:
        min_offer = min((o for o in paddle.market_offers if o.is_active), key=lambda o: o.price_brl, default=None)
        power = paddle.power_rating or 5
        control = paddle.control_rating or 5
        price = float(min_offer.price_brl) if min_offer else 0.0
        rating = round((power + control) / 2, 1)
        # isHiddenGem: rating >= 7 AND price < 600 AND not featured
        is_gem = rating >= 7 and price > 0 and price < 600 and not paddle.is_featured
        return {
            "id": seq_id,
            "name": paddle.model_name,
            "brand": paddle.brand.name if paddle.brand else "Unknown",
            "price": price,
            "rating": rating,
            "imageUrl": paddle.image_url,
            "coreThickness": float(paddle.core_thickness_mm) if paddle.core_thickness_mm else None,
            "surface": paddle.surface_material,
            "handle": None,
            "swingWeight": None,
            "powerScore": power,
            "controlScore": control,
            "weightSensation": None,
            "weightSensationDescription": None,
            "shopUrl": min_offer.product_url if min_offer else None,
            "isHiddenGem": is_gem,
            "valueCostBenefit": None,
        }
    ```

    **Endpoint 2: GET /api/paddles**
    Query params: `brand?: str`, `minPrice?: float`, `maxPrice?: float`, `coreThickness?: float`, `search?: str`, `limit: int = 50`, `offset: int = 0`.
    Query PaddleMaster with `selectinload(PaddleMaster.brand)` and `selectinload(PaddleMaster.market_offers)` and `selectinload(MarketOffer.store)` (if needed).

    - `coreThickness`: filter by `PaddleMaster.core_thickness_mm == coreThickness`
    - `search`: filter by `PaddleMaster.model_name.ilike(f"%{search}%")`
    Use `row_number()` for sequential integer IDs (order by `created_at`).
    Return `{"paddles": [...], "total": count}` matching `PaddleListResponse` schema.

    **Endpoint 3: GET /api/paddles/{id}**
    `id` is a sequential integer. Query all paddles with row_number, find the one matching `id`. Return single Paddle dict. Return 404 if not found.

    **Endpoint 4: POST /api/quiz/recommend**
    Accept body matching `QuizAnswers` schema. Map fields:
    - `budget`: "under300" -> max 300, "300to600" -> max 600, "600to900" -> max 900, "over900" -> max 99999
    - `skillLevel`, `playStyle`: pass to existing recommendation logic
    Build a `RecommendationRequest` (from `app/schemas/user_profile.py`) and call the existing recommendation logic in `app/api/routes.py` or `app/api/endpoints/recommend.py`.
    Alternatively, query paddles directly and build the recommendation:
    - Filter by budget range
    - Score by playStyle alignment (power style -> high powerScore paddles, control -> high controlScore, etc.)
    - Return `{"topPick": Paddle, "alternatives": Paddle[], "reasoning": str, "idealSpec": {...}}`

    **Endpoint 5: POST /api/leads**
    Accept `{"name": str, "email": str, "quizAnswers"?: ..., "recommendedPaddleId"?: int}`.
    Create Lead with `email` and `name`. Ignore `quizAnswers` and `recommendedPaddleId` (not in Lead model).
    Return `{"success": true, "message": "Lead capturado com sucesso"}` — NOT the LeadRead schema.

    **Endpoint 6: POST /api/chat**
    Accept `{"message": str, "conversationHistory"?: [{role, content}], "recommendedPaddleId"?: int, "quizAnswers"?: QuizAnswers}`.
    Build `ChatRequest` for existing chat logic: transform `message` + `conversationHistory` into `messages: [{role: "user", content: message}]` format, add `context` string from quizAnswers if present.
    Call existing LLM chat logic (from routes.py `coach_chat` function or recommend.py `post_chat`).
    Return `{"reply": str, "suggestedPaddleIds": []}`.

    **Endpoint 7: GET /api/stats/market**
    Query all PaddleMaster with loaded brand and market_offers.
    Calculate:
    - `totalPaddles`: count
    - `averagePrice`: mean of min prices
    - `bestValue`: paddle with highest rating/price ratio
    - `topPower`: paddle with highest powerScore
    - `coreThicknessDistribution`: `{"16mm": 5, "14mm": 3, ...}` grouped by core_thickness_mm
    - `priceRangeDistribution`: `{"0-300": N, "300-600": N, "600-900": N, "900+": N}`
    - `surfaceDistribution`: grouped by surface_material
    - `powerVsControlData`: array of `{name, brand, power, control, price}` for up to 30 paddles
    - `marketInsight`: string like "X% das raquetes usam nucleo de Ymm"
    Return dict matching `MarketStats` schema.

    **Endpoint 8: GET /api/stats/brands**
    Query all PaddleMaster grouped by brand.
    Return array of `{"brand": str, "count": int, "avgPrice": float, "avgRating": float, "marketShare": float}`.
    Sort by count descending.

    **Endpoint 9: GET /api/stats/hidden-gems**
    Query paddles where `isHiddenGem` logic applies (rating >= 7, price < 600, not featured).
    Return array of Paddle dicts. Limit 10.

    **IMPORTANT:** The router prefix is `/api` (NOT `/api/v1`). Endpoints define paths like `/paddles`, `/quiz/recommend`, `/stats/market`, etc. Combined with prefix: `/api/paddles`, `/api/quiz/recommend`, etc. This matches the Orval client paths exactly.
